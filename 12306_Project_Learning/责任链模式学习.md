# 责任链模式学习（结合12306项目）

## 一、责任链模式是什么？

**一句话解释：** 把多个处理器串成一条链，请求依次经过每个处理器，每个处理器只负责自己那部分逻辑。

**类比：** 公司报销流程 —— 员工提交 → 组长审批 → 经理审批 → 财务审批，每一层只管自己职责范围内的审批。

---

## 二、项目里哪些代码用了责任链？

### 核心框架层

路径：`frameworks/designpattern/.../chain/`

| 类名                      | 职责                                               |
| ------------------------- | -------------------------------------------------- |
| `AbstractChainHandler<T>` | 定义每个处理器的接口（handler方法 + mark标识）     |
| `AbstractChainContext<T>` | 责任链容器，启动时自动收集所有Handler并按Order排序 |

### 购票校验链

路径：`ticket-service/.../filter/purchase/`

| 执行顺序 | Handler 类                                    | 职责                             |
| -------- | --------------------------------------------- | -------------------------------- |
| Order=0  | `TrainPurchaseTicketParamNotNullChainHandler` | 必填参数非空校验                 |
| Order=10 | `TrainPurchaseTicketParamVerifyChainHandler`  | 列车是否存在、是否在售、站点顺序 |
| Order=20 | `TrainPurchaseTicketParamStockChainHandler`   | 余票库存是否充足                 |
| Order=30 | `TrainPurchaseTicketRepeatChainHandler`       | 重复购票校验                     |

### 触发点

`TicketServiceImpl.java` 中，购票前一行代码触发整条链：

```java
purchaseTicketAbstractChainContext.handler(
    TicketChainMarkEnum.TRAIN_PURCHASE_TICKET_FILTER.name(),
    requestParam
);
```

除购票外，**查票**、**退票**、**用户注册**也各有自己的责任链。

## 三、怎么体现可维护性？

**每个 Handler 职责单一，互不干扰。**

比如以前如果把校验写在一个 Service 方法里：

```java
// 难以维护的写法
public void purchaseTicket(req) {
    // 非空校验...50行
    // 列车校验...80行
    // 库存校验...60行
    // 重复购票校验...40行
    // 真正的购票逻辑...
}
```

用责任链之后，每个 Handler 是独立的类，**改库存校验逻辑只动 `StockChainHandler`**，不会影响其他校验，也不会误改购票核心逻辑。测试时也可以**单独测每个 Handler**。

---

## 四、怎么体现可扩展性？

**新增校验规则 = 新建一个类，不改任何现有代码（符合开闭原则）。**

比如以后要加一个"同一身份证当天只能买3张票"的校验：

1. 新建 `TrainPurchaseTicketIdCardLimitChainHandler` 实现 `TrainPurchaseTicketChainFilter`
2. 加上 `@Component`，设置 `getOrder()` 返回 `25`（插在库存校验和重复校验之间）
3. **完成，其他代码零修改**

这得益于 `AbstractChainContext` 启动时用 Spring 的 `getBeansOfType()` 自动扫描所有 Handler 注册进去，新加的 Bean 会自动被发现并加入链中。

## 五、面试回答模板

> "购票流程涉及多个校验步骤，我们用责任链模式把它们解耦。框架层定义了 `AbstractChainHandler` 接口和 `AbstractChainContext` 容器，容器在启动时自动扫描所有 Handler、按 Order 排序。购票场景下有4个 Handler 依次执行：参数非空 → 列车合法性 → 库存检查 → 重复购票。Service 层只需一行 `chainContext.handler(mark, req)` 就触发整条链。
>
> 可维护性体现在每个 Handler 职责单一，修改库存校验不会影响参数校验的代码。可扩展性体现在新增校验规则只需新建一个类并加 `@Component`，Spring 自动发现并注册，现有代码零修改，符合开闭原则。"
