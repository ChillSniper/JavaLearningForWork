# 项目组群友 Qorder 一面

1. 你怎么理解 MCP？MCP 在 Agent 全流程中处于什么位置？
2. 一个完整 Agent Harness 的执行流程是什么？
3. Agent 的上下文应该如何组织和管理？
4. Claude Code 的上下文压缩是怎么实现的？
5. 为什么有些 Agent 使用 TypeScript/JavaScript，有些使用 Python？
6. TypeScript、JavaScript、Python、Java 用来开发 Agent，各有什么区别？
7. Web 服务也可以使用 TypeScript，为什么还要选 Python？
8. Python 性能不是比较慢吗？会不会影响 Agent 服务？
9. 你的上下文缓存命中率怎么样？
10. 怎么保证上下文结构和顺序，避免影响缓存命中？
11. 你怎么理解 Agent 的 Memory？
12. 短期记忆和长期记忆有什么区别？
13. 记忆是怎么抽取出来的？
14. 你使用的 Mem0 是怎么工作的？
15. 为什么选择 Mem0？你具体做了什么集成或修改？
16. 大段工具调用结果为什么要落盘，而不是一直放在模型上下文里？
17. 工具结果落盘后，模型后续如何重新找到并读取？
18. 上下文越来越长时，哪些内容应该删除，哪些应该保留？
19. 探测性对话、旧工具调用结果、`read/grep` 记录分别怎么处理？
20. 上下文压缩是一次性摘要，还是渐进式、多层级压缩？
21. 压缩时是否会结合历史操作和文件引用？
22. 能否对已经压缩过的上下文继续压缩？连续压缩会损失什么？
23. 直接压缩当前会话，与总结成 `.md` 后开新会话相比，哪个更好？
24. 上下文顺序为什么会影响 KV Cache 命中？
25. Session 级上下文和长期 Memory 的边界是什么？
26. Memory 检索时如何综合相关性、时间权重和当前任务？
27. 如何避免把错误、过期或无价值的信息写入长期记忆？
28. 项目中的 Context、Memory、Tool、MCP 是如何串成完整闭环的？

这场面试真正考察的不是会不会背 Agent 名词，而是你是否实际处理过：工具输出膨胀、上下文淘汰、压缩信息损失、KV Cache、记忆抽取与检索，以及技术选型。屏幕共享看项目也不算独立题目，更像是面试官用代码验证你讲的设计是否真的实现了。
