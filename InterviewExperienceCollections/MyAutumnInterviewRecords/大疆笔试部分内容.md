## 逐题解答

### 1. `vector` 末尾追加元素的时间复杂度

**答案：平均（更准确地说是均摊）时间复杂度为 `O(1)`，单次最坏时间复杂度为 `O(n)`。**

当 `vector` 还有剩余容量时，`push_back` 只需在末尾构造一个元素，是 `O(1)`。容量不足时，需要申请一块更大的连续内存，并把原来的 `n` 个元素移动或复制过去，因此这一次是 `O(n)`。由于扩容通常按倍数增长，连续执行多次追加操作时，总成本均摊到每次仍是 `O(1)`。

### 2. 堆排序是否稳定

**答案：堆排序不稳定。**

建堆、调整堆以及把堆顶与末尾元素交换时，可能改变两个相等元素的原始先后顺序。例如两个关键字相同的元素可能因为一次跨越较远位置的交换而发生相对次序变化。因此，堆排序的时间复杂度是 `O(n log n)`，额外空间通常是 `O(1)`，但它不是稳定排序。

### 3. 拓扑排序适用于什么图

**答案：如果题目问“什么图可以得到拓扑序”，应选 DAG，即有向无环图。**

拓扑排序处理的是有向图；只有图中不存在有向环时，才能得到包含全部顶点的拓扑序。因此更严谨的说法是：可以对一般有向图尝试执行拓扑排序，但能够成功生成完整拓扑序的充要条件是该图为 DAG。Kahn 算法处理结束后若输出顶点数小于总顶点数，还可以据此判断图中存在环。

### 4. 通过空指针调用不访问成员的非虚成员函数

**答案：按照 C++ 标准，这是未定义行为（Undefined Behavior，UB）。**

例如：

```cpp
struct A {
    void f() { }
};

A* p = nullptr;
p->f(); // 未定义行为
```

非虚函数可能由编译器直接静态确定地址，因此某些编译器和优化级别下，这段程序看起来能够运行；但调用非静态成员函数仍需要一个有效对象作为隐含的 `this`，空指针并不指向有效对象。函数体没有访问成员，也不能让该调用变成标准保证的合法行为，不能依赖“实测没崩”。

### 5. 函数模板与非模板函数重载时如何决议

**答案：先按正常重载规则选择最佳可行函数；只有双方的匹配程度同样好时，才优先选择非模板函数。它不是无条件优先非模板，更不是随机选择。**

```cpp
void f(int) { }

template <class T>
void f(T) { }

f(1);    // 两者都是精确匹配，选择非模板 f(int)
f('a');  // 模板 f(char) 是精确匹配，非模板需要 char -> int，选择模板
```

基本过程是：先形成候选集，排除不可行函数，再比较隐式转换序列；若转换质量相同，非模板函数优先于函数模板特化。如果应用全部决胜规则后仍没有唯一最佳函数，才会产生二义性编译错误。

### 6. STL 迭代器失效

**按当前记录复原题意，如果问“哪些操作会导致所描述的迭代器失效”，应选 A、B、D；C 的完整文字需要结合原选项判断。**

- A，`vector` 扩容：正确。重新分配内存后，所有指向该 `vector` 元素的迭代器、指针和引用，包括旧的 `end()`，全部失效。
- B，`vector` 在中间 `erase`：正确。被删除位置以及该位置之后的迭代器和引用失效；删除位置之前的仍有效。
- C，`list insert`：插入本身不会使已有元素的迭代器和引用失效。如果原选项说“会使其他迭代器失效”，该项错误；如果说“其他迭代器仍有效”，该项正确。
- D，`map/set erase`：正确。只有指向被删除元素的迭代器和引用失效，其他元素的迭代器和引用仍然有效。

补充：`vector` 末尾插入但未扩容时，原有元素的迭代器和引用仍有效，不过旧的 `end()` 会失效。

### 7. 哪些情况属于未定义行为

**答案：题目列出的四项全部属于未定义行为。**

1. 对同一个标量对象进行彼此无顺序关系的多次修改，例如 `i++ + i++`。
2. 通过下标或指针访问原生数组边界之外的元素。
3. 解引用空指针。
4. 有符号整数发生算术溢出。

“未定义行为”不是“程序一定崩溃”，而是 C++ 标准不再约束程序结果。程序可能崩溃、输出看似正常的结果，也可能在编译器优化后出现完全不同的行为。无符号整数溢出则按模 `2^N` 回绕，不属于 UB。

### 8. 返回局部 `string` 内部指针的问题

**答案：函数返回了悬空指针。**

```cpp
const char* func() {
    std::string s = "hi";
    return &s[0];
}
```

`&s[0]` 指向 `s` 管理的内部缓冲区；函数返回时局部对象 `s` 被析构，这块缓冲区的生命周期结束，返回的指针随即悬空。之后通过它读取数据属于未定义行为。改成 `return s.c_str()` 也不能解决生命周期问题。

通常应直接按值返回：

```cpp
std::string func() {
    return "hi";
}
```

现代 C++ 会通过返回值优化或移动语义高效地完成返回。如果接口必须返回 `const char*`，则必须由调用者提供缓冲区，或者确保被指向字符数组的生命周期长于调用方的使用期。

### 9. 同一进程中的线程共享什么，各自独立持有什么

**答案：线程共享进程级资源，但各自拥有独立的执行现场。**

同一进程内的线程通常共享：

- 同一个虚拟地址空间，包括代码段、全局/静态数据和堆。
- 进程打开的文件描述符或句柄、当前工作目录等进程级资源。
- 同一个进程 ID 和大部分进程级状态。

每个线程通常独立拥有：

- 线程栈。
- CPU 寄存器、程序计数器等上下文。
- 线程 ID、调度状态。
- 线程局部存储，即 `thread_local`/TLS 数据。

因此线程间通信方便，但访问共享可变数据时必须用互斥锁、原子变量等方式同步，否则可能产生数据竞争；C++ 中数据竞争本身就是未定义行为。

### 10. `fork` 后子进程会不会修改父进程中的变量

**答案：通常不会。**

`fork` 后，子进程得到父进程地址空间的逻辑副本。操作系统一般使用写时复制（Copy-on-Write）：父子进程起初可以映射相同物理页，一方写入时才复制相应页面。因此子进程修改普通全局变量、堆变量或栈变量，只会改变子进程自己的副本，不会改变父进程中的值。

边界情况是显式的进程间共享资源，例如 `mmap(..., MAP_SHARED, ...)`、共享内存、管道或文件。父子进程继承的文件描述符通常引用同一个内核打开文件对象，所以文件偏移等内核状态可能相互影响。若多线程进程调用 `fork`，子进程只保留发起 `fork` 的那个线程，这也是面试中的常见追问。

### 11. 用于互斥时初始值是多少

**答案：如果题目把互斥抽象成二元信号量，初始值应设为 `1`。**

`1` 表示资源当前可用。一个线程执行 `wait/P` 后把它从 `1` 变成 `0` 并进入临界区，其他线程只能等待；离开临界区时执行 `signal/V`，使其恢复为 `1`。

严格来说，真正的 `mutex` 通常描述为“初始处于未加锁状态”，而不是设置一个数值；例如 POSIX 互斥锁使用 `PTHREAD_MUTEX_INITIALIZER`，C++ 使用默认构造的 `std::mutex`。只有题目实际问信号量计数时，才回答数值 `1`。

### 12. 微内核架构

**答案：微内核属于操作系统内核架构。它把内核态中的功能压缩到最小，把更多系统服务放到用户态进程中。**

微内核通常只在内核态保留线程调度、进程间通信（IPC）、基础地址空间管理和中断等最核心机制；文件系统、网络协议栈、设备驱动等服务尽量作为用户态服务运行。各服务通过消息传递协作。

主要优点是故障隔离更好、内核更小、更容易维护或形式化验证：某个用户态驱动崩溃时，通常不必直接拖垮整个内核。主要代价是服务之间需要更多 IPC、用户态/内核态切换和上下文切换，设计不当会带来性能开销，系统协作也更复杂。MINIX 3、QNX、seL4 是常见例子；Linux 是宏内核，Windows NT 和 XNU 通常被归为混合内核而不是纯微内核。

### 13. TCP 与 UDP 的区别

**答案：TCP 面向连接，提供可靠、有序的字节流；UDP 无连接，按数据报发送，不保证可靠性和顺序。**

| 对比项 | TCP | UDP |
| --- | --- | --- |
| 连接 | 通信前需要建立连接 | 不需要建立连接 |
| 数据形式 | 字节流，没有消息边界 | 数据报，保留消息边界 |
| 可靠性 | 通过序号、确认、重传等机制保证可靠、有序、去重 | 可能丢失、乱序或重复，应用层按需处理 |
| 流量与拥塞控制 | 有 | 协议本身没有 |
| 开销 | 首部和状态维护较多 | 首部小、处理简单、时延通常较低 |
| 通信方式 | 一对一连接 | 支持一对一，也可用于广播和多播 |
| 常见场景 | HTTP/1.1、HTTP/2、数据库连接、文件传输 | DNS、音视频实时传输、在线游戏、QUIC 的底层承载 |

选择时不能简单理解成“TCP 慢、UDP 快”。如果业务在 UDP 之上重新实现确认、重传、拥塞控制和加密，整体成本同样可能很高；QUIC 就是在 UDP 之上实现这些能力，并改善了连接建立和多路复用等问题。

### 14. MySQL 的 `AVG()` 如何处理 `NULL`

**答案：`AVG(column)` 会忽略 `NULL`，分子只累加非 `NULL` 值，分母也是非 `NULL` 值的数量。**

例如数据为 `10、20、NULL`：

```sql
SELECT AVG(score) FROM t;
```

结果是 `(10 + 20) / 2 = 15`，不是除以 `3`。它在语义上可理解为：

```sql
SUM(score) / COUNT(score)
```

其中 `COUNT(score)` 同样不统计 `NULL`，而 `COUNT(*)` 会统计所有行。如果没有任何非 `NULL` 值，例如所有值都是 `NULL` 或结果集为空，`AVG()` 返回 `NULL`。只有业务明确要求把缺失值按 `0` 计算时，才使用 `AVG(COALESCE(score, 0))`；这会把这些行计入分母，语义已经发生变化。

### 15. InnoDB 的可重复读及其细节

**核心答案：在 InnoDB 的 `REPEATABLE READ`（RR）级别下，普通 `SELECT` 主要依靠 MVCC 和事务级 Read View 实现可重复读；加锁读以及 `UPDATE`、`DELETE` 属于当前读，主要依靠记录锁、间隙锁和 Next-Key Lock 处理并发。**

#### 15.1 RR 解决什么问题

可重复读保证同一事务中，对同一快照执行多次普通一致性读时，不会因为其他事务已经提交修改而出现前后读取不一致。它防止脏读和不可重复读。InnoDB 还分别通过 MVCC 快照和 Next-Key Lock，应对普通快照读与加锁范围读中的幻读问题。

#### 15.2 MVCC 和 Read View 怎样工作

InnoDB 的聚簇索引记录包含事务 ID、回滚指针等隐藏信息。数据被修改后，旧版本可通过 undo log 版本链重建。Read View 记录创建快照时活跃事务的范围，InnoDB 根据可见性规则决定当前事务应看到哪个版本。

- RR：同一事务通常在第一次普通一致性读时创建 Read View，后续普通一致性读复用该快照。
- RC（`READ COMMITTED`）：每条普通一致性读语句都会创建新的 Read View，所以能看到其他事务在两次查询之间提交的结果。
- 当前事务自己在快照建立后所做的修改，对自己仍然可见。
- 如果希望事务开始时就建立快照，可使用 `START TRANSACTION WITH CONSISTENT SNAPSHOT`。

#### 15.3 快照读与当前读必须区分

| 类型 | 常见语句 | 读取和加锁特点 |
| --- | --- | --- |
| 快照读 | 普通 `SELECT` | 读取 Read View 可见的数据版本，通常不加记录锁，不会被普通写锁阻塞 |
| 当前读/加锁读 | `SELECT ... FOR UPDATE`、`SELECT ... FOR SHARE` | 读取较新的可用版本，并对扫描到的索引记录或范围加锁 |
| 当前读/写操作 | `UPDATE`、`DELETE` | 按当前数据进行匹配和修改，并加排他锁 |

因此，不能笼统地说“RR 下所有查询永远都读取事务开始时的数据”。普通 `SELECT` 与加锁读、写语句观察数据的方式不同。在同一事务中混用快照读和当前读，可能看到两种不同的数据状态。

#### 15.4 InnoDB 怎样处理幻读

- 对普通快照读：事务复用同一个 Read View，其他事务后来插入并提交的行在该快照中不可见，所以重复执行相同普通查询通常不会看到新增的“幻影行”。
- 对加锁范围读或范围修改：InnoDB 在 RR 下通常对实际扫描的索引范围使用 Next-Key Lock，也就是“记录锁 + 前面的间隙锁”，阻止其他事务在被锁范围的间隙中插入新记录。
- 如果通过唯一索引按唯一值等值查询，并且目标记录存在，通常只需要记录锁，不需要锁前面的间隙。

锁加在哪里取决于实际使用的索引和扫描范围，而不是抽象地锁住 `WHERE` 条件本身。缺少合适索引时，扫描和加锁范围可能很大，导致并发性明显下降。

#### 15.5 RR 不等于串行化

RR 仍然允许事务并发执行，并不能替代完整的业务并发控制。对于“先查余额，再根据查询结果更新”之类依赖最新值的读改写逻辑，应该根据场景使用 `SELECT ... FOR UPDATE`、条件更新、乐观锁版本号或 `SERIALIZABLE`，并对死锁和锁等待进行重试处理。只依赖一次普通快照读，仍可能产生业务层面的并发异常。

面试时可以总结为：**“InnoDB 的 RR 对普通读使用事务级 MVCC 快照，对加锁读和写操作读取当前版本，并通过记录锁、间隙锁和 Next-Key Lock 保护索引范围；所以讨论可重复读和幻读时，必须先说明是在谈快照读还是当前读。”**
