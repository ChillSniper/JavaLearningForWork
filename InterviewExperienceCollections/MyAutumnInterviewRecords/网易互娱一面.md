## C. C++、数据结构与内存

### 12. （按对话推断）什么是 C++ 智能指针？

**建议时长：60 秒。**

智能指针是利用 RAII 管理动态资源的对象：智能指针离开作用域时自动释放所拥有的资源，从而减少内存泄漏和异常路径上的清理错误。常见类型有：

- `std::unique_ptr<T>`：独占所有权，不能复制，只能移动，开销最小，默认优先使用。
- `std::shared_ptr<T>`：共享所有权，控制块维护引用计数，最后一个强引用销毁时释放对象。
- `std::weak_ptr<T>`：观察 `shared_ptr` 管理的对象但不增加强引用计数，使用前通过 `lock()` 获取临时 `shared_ptr`，可用于打破循环引用。

创建时优先使用 `std::make_unique` 和 `std::make_shared`。智能指针不是垃圾回收；错误的所有权模型、循环 `shared_ptr` 或把同一个裸指针交给多个智能指针，仍然会出问题。

### 13. 数组和链表有什么区别？

**建议时长：45～60 秒。**

数组或 `vector` 的元素通常连续存储，可以通过首地址和下标在 `O(1)` 时间随机访问；在中间插入或删除需要移动后续元素，通常是 `O(n)`。动态数组尾部追加在不扩容时是 `O(1)`，考虑偶尔扩容后是均摊 `O(1)`。

链表节点通常分散分配，只能沿指针访问，第 `i` 个元素需要 `O(n)`；如果已经拿到目标节点或其前驱，插入和删除可以是 `O(1)`，但寻找位置仍然是 `O(n)`。链表还要为每个节点保存指针，并承担更多分配和缓存未命中开销。

### 14. 保存相同内容时，数组和链表谁遍历更快？

**建议时长：30～45 秒。**

通常数组更快。虽然两者完整遍历的时间复杂度都是 `O(n)`，但数组连续存储，具有更好的空间局部性，CPU Cache Line 和硬件预取可以一次带入多个相邻元素；链表需要指针跳转，节点可能分散在不同缓存行，还多一次指针读取。

这不是“连续就绝对更快”的定理，实际结果还受元素大小、节点布局、内存分配器和访问模式影响，但对保存 1 到 10000 这类简单整数的顺序遍历，数组通常明显更有优势。

### 15. 程序可以从哪里分配内存？

**建议时长：60～90 秒。**

从对象生命周期看，常见存储区域包括：静态存储区保存全局变量和静态变量，生命周期贯穿进程；栈保存函数调用帧和自动变量，由进入、退出作用域自动管理，分配快但容量有限；堆用于运行时动态分配，生命周期由程序控制，灵活但有分配开销、碎片和泄漏风险。

在 C++ 中，`new` 分配内存并调用构造函数，`delete` 调用析构函数并释放内存；`malloc` 只返回一块原始字节，`free` 只释放，不处理构造和析构，二者不能混用。现代 C++ 应优先使用容器和智能指针。

底层上，运行库的堆分配器会复用已有内存块，必要时再通过操作系统接口申请或映射页面；具体是否使用 `brk`、`mmap` 或其他机制由平台和实现决定。对象池、Arena 和自定义 Allocator 可以降低高频小对象分配成本。

## D. 排序与操作系统

### 16. 你知道哪些排序算法？

**建议时长：45～60 秒。**

可以按复杂度和约束分类：冒泡、选择、插入排序平均是 `O(n^2)`，其中插入排序适合小规模或接近有序的数据；归并排序稳定，时间复杂度 `O(n log n)`，但通常需要 `O(n)` 额外空间；堆排序是 `O(n log n)` 且原地，但缓存局部性一般；快速排序平均 `O(n log n)`、最坏 `O(n^2)`，工程上通常通过随机化和退化保护获得很好的性能。

计数、桶和基数排序可以在满足值域或位数约束时接近线性复杂度，但不能笼统说它们对任意输入都是 `O(n)`。

### 17. 快速排序的过程是什么？

**建议时长：60 秒。**

先选择一个 `pivot`，通过分区把小于 `pivot` 的元素放到一侧，大于 `pivot` 的元素放到另一侧，再递归处理左右区间。关键是说清使用哪一种分区方案和不变量，不要把不同写法的指针移动规则混在一起。

下面使用双指针分区，`i` 从左找不小于 `pivot` 的元素，`j` 从右找不大于 `pivot` 的元素；当 `i <= j` 时交换并继续，结束后递归 `[left, j]` 和 `[i, right]`：

```cpp
#include <algorithm>
#include <vector>

void quickSort(std::vector<int>& nums, int left, int right) {
    if (left >= right) {
        return;
    }

    int pivot = nums[left + (right - left) / 2];
    int i = left;
    int j = right;
    while (i <= j) {
        while (nums[i] < pivot) {
            ++i;
        }
        while (nums[j] > pivot) {
            --j;
        }
        if (i <= j) {
            std::swap(nums[i], nums[j]);
            ++i;
            --j;
        }
    }

    if (left < j) {
        quickSort(nums, left, j);
    }
    if (i < right) {
        quickSort(nums, i, right);
    }
}
```

### 18. 快排复杂度和最好、最坏情况是什么？

**建议时长：45～60 秒。**

每层分区总共扫描 `O(n)` 个元素。如果每次都接近均匀分成两半，递归树高度是 `O(log n)`，时间复杂度是 `O(n log n)`，递归栈空间是 `O(log n)`；如果每次只能分出一个元素和剩余元素，递归高度退化为 `O(n)`，时间复杂度是 `O(n^2)`，栈空间也是 `O(n)`。

“原数组有序时一定最坏”取决于选取 pivot 的策略：若总选第一个或最后一个元素，有序输入会退化；若随机选 pivot 或取中间值，则不一定。工程实现常用随机化、三数取中、小区间插入排序和深度超限后切换堆排序来避免极端退化。

### 19. 什么是虚拟内存？

**建议时长：30～45 秒。**

虚拟内存是操作系统和硬件共同提供的地址空间抽象。每个进程看到自己的连续虚拟地址空间，实际访问时由 MMU 根据页表把虚拟页映射到物理页框；不同虚拟页也可以映射到同一物理页，用于共享库、共享内存和文件映射。

虚拟内存不等于磁盘，也不主要是为了提高“查询效率”。磁盘或交换空间只是在内存不足、按需加载等场景中可能使用的后备存储。

### 20. 虚拟内存解决什么问题？

**建议时长：45～60 秒。**

主要解决四类问题：第一，为进程提供隔离和访问保护，一个进程不能随意读写另一个进程的内存；第二，让程序使用统一的虚拟地址，不必关心物理内存实际放在哪里；第三，通过按需分页，只在访问时加载需要的页面，并允许虚拟地址空间大于当前物理内存；第四，支持共享内存、内存映射文件、写时复制等机制。

代价是页表占用、地址翻译和缺页处理开销，因此 CPU 使用 TLB 缓存近期的虚拟页到物理页映射。

### 21. 虚拟地址怎样转换成物理地址？

**建议时长：60 秒。**

CPU 把虚拟地址拆成虚拟页号和页内偏移。先查 TLB；命中后直接得到物理页框号，与原页内偏移拼成物理地址。TLB 未命中时，硬件或操作系统进行多级页表遍历，检查页表项中的物理页框和读写执行权限，再把映射写回 TLB。

如果页表项表示页面当前不在物理内存，就触发缺页异常。操作系统确认访问合法后分配页框，必要时从可执行文件、内存映射文件或交换区加载页面，更新页表，再重新执行指令；如果地址非法，就向进程报告访问错误。

## E. 网络与动态数组

### 22. TCP 和 UDP 有什么区别？

**建议时长：60 秒。**

TCP 面向连接，提供可靠、有序、无重复的字节流，并带有流量控制和拥塞控制；建立连接通常需要三次握手，关闭连接通常涉及四次挥手。UDP 无连接，按数据报发送，保留消息边界，但协议本身不保证到达、顺序或不重复，也没有 TCP 那套拥塞控制。

选择取决于业务目标。文件传输通常需要可靠性，常用 TCP；实时音视频和游戏状态同步更关注低延迟，常使用 UDP，再由应用层补充序号、重传、FEC 或状态快照。不能简单说“UDP 适合传大文件”。QUIC 虽然基于 UDP，但可靠性和拥塞控制由 QUIC 自己实现。

### 23. TCP 怎样保证可靠、有序传输？

**建议时长：60～90 秒。**

TCP 依靠一组机制共同保证：序列号标识字节位置；接收端用累计 ACK 和可选 SACK 告知已经收到的范围；发送端通过重传计时器和快速重传恢复丢失数据；校验和检测传输错误；接收端按序重组并丢弃重复数据；滑动窗口实现流量控制，避免压垮接收端；拥塞窗口和慢启动、拥塞避免等算法控制网络中的发送速率。

三次握手的作用主要是确认双方收发能力、同步初始序列号和协商参数。它只是建立连接的一部分，不能单独解释整个传输阶段的可靠性。

### 24. TCP 丢包后怎样检测和恢复？

**建议时长：45～60 秒。**

如果某个报文段丢失，接收端后续收到乱序数据时会持续 ACK 当前期望的下一个序列号。发送端收到足够的重复 ACK 后可以触发快速重传；如果没有足够的后续数据产生重复 ACK，则重传计时器到期后重传。启用 SACK 时，接收端还能明确告诉发送端哪些区间已经收到，减少不必要重传。

重传后接收端按序重组，重复报文根据序列号丢弃。发送端还会根据丢包信号调整拥塞窗口，因为 TCP 通常把丢包视为网络拥塞的迹象。

### 25. 什么是动态数组？是否使用过 `vector`？

**建议时长：30～45 秒。**

动态数组在逻辑上像数组一样连续存储并支持 `O(1)` 随机访问，但容量可以在运行时增长。C++ 中最常用的实现是 `std::vector`，它维护元素数量 `size` 和已分配槽位数量 `capacity`，并通过自动扩容支持尾部追加。

`vector` 通常应作为顺序容器的默认选择，因为它紧凑、缓存友好，并能与标准算法良好配合。

### 26. `vector` 插入元素和扩容的过程是什么？

**建议时长：60 秒。**

如果 `size < capacity`，尾部 `push_back` 会直接在末尾未初始化空间构造新元素，`size` 加一，`capacity` 不变，复杂度是 `O(1)`。如果空间不足，`vector` 会申请一块更大的连续内存，把旧元素移动或复制到新空间，在末尾构造新元素，然后销毁旧元素并释放旧内存；这次操作是 `O(n)`，但按几何比例扩容后，连续多次尾插的均摊复杂度仍是 `O(1)`。

中间位置插入还需要向后移动插入点之后的元素，通常是 `O(n)`。发生扩容时，指向旧元素的迭代器、引用和指针全部失效；未扩容时，插入点及其后的迭代器通常也会失效。

### 27. `vector` 按多少比例扩容？

**建议时长：30～45 秒。**

C++ 标准没有规定固定扩容倍数，只要求容器满足相应复杂度和语义。常见实现采用大约 1.5 倍或 2 倍的几何增长，但具体策略取决于标准库版本、平台、当前大小和插入数量，代码不能依赖某个固定比例。

如果预先知道元素规模，可以调用 `reserve(n)` 一次预留容量，减少反复扩容；`reserve` 只改变 `capacity`，不创建元素，也不改变 `size`。`resize(n)` 则会改变元素数量，必要时构造或销毁元素。

## 六、本场暴露的问题与复习重点
